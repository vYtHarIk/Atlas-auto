# АТЛАС АВТО

Учебный проект по варианту 11 «Запись на тест-драйв и бронирование автомобилей
в автосалоне». Выполнено **оба занятии** из блока «7–9. Разработка
интерфейса пользователя»: каркас Django-проекта, шаблоны, статика, именованные
маршруты и главная страница по макету занятия 6.

## Стек

- Python 3.14, Django 6.1
- SQLite (на следующих занятиях подключаются модели)
- HTML, CSS, JavaScript без фреймворков
- Шрифты: Inter (заголовки) и Roboto (текст); если они не установлены
  в системе, используется системный запасной вариант

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Сайт откроется на <http://127.0.0.1:8000/>.

Секретный ключ и режим отладки читаются из переменных окружения
`DJANGO_SECRET_KEY` и `DJANGO_DEBUG`; локальные значения по умолчанию годятся
только для учебной машины.

## Структура

```
config/           настройки проекта и корневой urls.py
autosalon/        приложение автосалона: views.py, urls.py, demo_data.py
templates/        base.html и шаблоны страниц
static/css/       main.css — стили и переменные из UI-kit
static/js/        main.js — меню-бургер
static/img/       изображения автомобилей и favicon
```

### Маршруты

| Имя | Адрес | Назначение |
| --- | --- | --- |
| `autosalon:home` | `/` | Главная страница |
| `autosalon:catalog` | `/catalog/` | Каталог автомобилей |
| `autosalon:car_detail` | `/catalog/<slug>/` | Карточка автомобиля |
| `autosalon:test_drive` | `/test-drive/` | Запись на тест-драйв |
| `autosalon:trade_in` | `/trade-in/` | Оценка авто в трейд-ин |
| `autosalon:about` | `/about/` | О салоне |
| `autosalon:contacts` | `/contacts/` | Контакты |
| `autosalon:register` | `/register/` | Регистрация |
| `autosalon:privacy` | `/privacy/` | Политика конфиденциальности |

Все ссылки в шаблонах строятся через `{% url %}`, нигде не используются
строковые адреса.

## Что сделано в занятии 8
- Разработка страниц проекта:** сверстаны и настроены основные страницы веб-приложения (`autosalon`), включая главную страницу, каталог автомобилей, страницу детальной карточки автомобиля, страницу оформления заявки / обратной связи, профиль / личный кабинет, информационную страницу о компании и страницу результатов поиска.
- Подключение данных из базы данных:** представления (`views.py`) передают реальные записи из моделей проекта в Django-шаблоны. В шаблонах используются циклы (`{% for %}`), условные конструкции (`{% if %}`), встроенные фильтры (`date`, `floatformat`, `truncatechars`) и пагинация по 20 записей на страницу. Весь демонстрационный текст заменён актуальными данными из БД.
- Сетка и адаптивность:** макеты построены с использованием CSS Grid и Flexbox. Вёрстка адаптирована под разрешения **360 px, 768 px, 1024 px и 1440 px** — отсутствует горизонтальная прокрутка, интерактивные элементы имеют высоту не менее 40 px, а на мобильных устройствах реализовано меню-бургер.
- Оптимизация изображений и организация CSS:** изображения оптимизированы по размеру и весу, снабжены атрибутами `width`, `height`, `alt` и ленивой загрузкой (`loading="lazy"`) для блоков ниже первого экрана. Стили вынесены в отдельные CSS-файлы с использованием CSS-переменных (цвета и отступы из UI-kit) без инлайн-атрибутов `style`.

## Что сделано в занятии 9
- Формы Django и серверная валидация:** реализованы формы на базе `Form` / `ModelForm` с защитой `{% csrf_token %}`. Настроена серверная валидация данных, отображение сообщений об ошибках рядом с соответствующими полями, сохранение введённых пользователем значений при ошибке, вывод уведомлений через `django.contrib.messages` и редирект после успешной отправки.
- Клиентская валидация (JavaScript):** добавлена предварительная проверка обязательных полей, формата email и номера телефона, а также допустимой длины текста перед отправкой формы на сервер.
- Динамические элементы без перезагрузки страницы:** реализованы интерактивные элементы интерфейса (живой поиск / фильтрация каталога, модальные окна, слайдер, добавление в избранное / подгрузка карточек).
- Асинхронное взаимодействие (`Fetch API`):** настроен обмен данными с Django-представлением в формате JSON через `fetch` с индикатором загрузки и динамическим обновлением фрагментов страницы без перезагрузки.
- Тестирование и проверка качества:** проведена проверка HTML-разметки через W3C Markup Validator (0 ошибок), валидация стилей в W3C CSS Validator, проверка отсутствия ошибок в консоли браузера на всех страницах, а также аудит мобильной версии в Chrome Lighthouse (показатели Performance и Accessibility ≥ 85).
